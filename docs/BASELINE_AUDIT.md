# 点课成题-课件刷题工坊 v2.0 基线审计报告（BASELINE_AUDIT）

> 审计对象：`courseware-quiz-builder` v1（提交于星辰杯初版，含 11-11 图片能力升级）
> 审计时间：2026-11-12
> 审计方式：逐文件通读全部 5 个核心文件（SKILL.md 119 行 / extract_text.py 337 行 / quiz_toolkit.py 595 行 / quiz-format.md 168 行 / quiz-template.html 435 行），以下每项问题均标注代码位置与复现方式，未实测项明确标注。

## 一、现有数据流与调用链（实测绘制）

```
用户材料 (.pptx/.docx/.pdf/.txt/.md)
   │
   ▼
scripts/extract_text.py          ← 阶段1：文本+图片提取（stdlib 解析 OOXML zip）
   │  输出: 合并文本(【第N页】标记) + 图片目录(每源文件子目录)
   ▼
LLM 通读材料 → 手写 quiz.json    ← 阶段2：出题（无中间结构化产物）
   │
   ▼
scripts/quiz_toolkit.py validate ← 阶段3：结构质检（字段/题型/答案/查重/图片白名单+魔数）
   │  (ERROR 拦截产出)
   ▼
scripts/quiz_toolkit.py build    ← 阶段4：渲染
   │  ├→ 题库-<主题>.md          (题目区/答案解析区分离, 图片旁挂文件夹)
   ├→ 刷题页-<主题>.html         (__QUIZ_DATA__ 注入, 图片@key共享内嵌base64)
   └→ 图片-<主题>/               (MD 引用)
   │
   ▼
浏览器打开刷题页（localStorage 记录作答, 交卷判分, 只看错题筛选, 重做全部）
```

**关键缺陷：链路中不存在任何「材料结构化清单」中间产物**。quiz.json 的 source_ref（如"课件第3页"）是 LLM 手写字符串，脚本仅检查非空——**来源不可核验**。

## 二、逐项审计结果（对应任务书 10 项检查）

### A1. PPTX 文本提取的标签匹配方式 —— 【已确认缺陷，P0】

`extract_text.py:58`：`re.findall(r"<a:t>(.*?)</a:t>", xml, re.S)`

- 只匹配**无属性**的 `<a:t>` 节点。WPS/LibreOffice/部分导出工具会生成 `<a:t xml:space="preserve">文本</a:t>`（带属性形式），该正则**整节点漏掉**。
- 同文件 `extract_docx.py:77` 用的是 `<w:t[^>]*>`（带属性兼容），**两处不一致**，证明 pptx 侧是遗漏而非设计取舍。
- 复现：构造含 `<a:t xml:space="preserve">X</a:t>` 的 slide xml → 提取结果不含 X。
- 附带：纯字符串正则无法处理 CDATA、注释内伪标签等 XML 边界；pptx 表格(a:tbl)文本可被匹配但**行列结构丢失**。

### A2. 图片魔数校验与扩展名一致性 —— 【已确认缺陷，与文档声明不符，P1】

`quiz_toolkit.py:41-55` `_magic_ok()`：只要文件头匹配**任意一种**已知图片魔数（PNG/JPEG/GIF/WEBP 任一）即通过。

- 后果：GIF 内容改名为 `.png` 也能通过（魔数≠扩展名一致性校验）。文档 `quiz-format.md:138` 却声称"魔数与扩展名一致（防伪造）"——**文档与实现不符**。
- 影响：HTML 内嵌时 MIME 按扩展名推导（`IMG_MIME`），GIF-as-png 会以 `data:image/png` 装载；浏览器因嗅探通常仍能渲染，实际风险低，但属于声明失实 + 校验不严格。
- 修复：按扩展名映射到期望魔数前缀，逐一比对。

### A3. source_ref 仅检查非空 —— 【已确认缺陷，核心差距，P0】

`quiz_toolkit.py:184-186`：`source_ref` 只要求非空字符串。

- LLM 手写"第41页"“材料第2组”，脚本无法验证页码是否存在、是否存在该材料片段。**"每道题必须有材料依据"只是流程约定，无任何技术强制**。
- 任务书第四节"三层检查"中的 B 层（确定性来源核验）完全缺失，C 层（语义复核）无记录载体（无 evidence_status / verification_notes 字段）。

### A4. 题库质检混淆"结构正确"与"内容正确" —— 【已确认缺陷，P0】

现有 validate 全部 14 项检查均为**结构/格式层面**（字段、枚举、下标范围、查重、图片安全）。但 SKILL.md:21 声称"确定性质检"、交付报告写"质检通过"，用户易理解为"内容正确已验证"。

- 缺失：来源核验（见 A3）、证据字段、语义复核结论的记录与展示。
- 任务书明确要求："规则核验不等于语义真实性核验"，需要明确分层标注。

### A5. HTML 无独立错题重练流程 —— 【已确认缺陷，P1】

`quiz-template.html:104`："只看错题"是**列表过滤器**（wrongOnly），非重练流程；`:421`"重做全部"会 `localStorage.removeItem` **清空全部记录**。

- 无"重做错题"独立入口、无错题分组、无错误原因展示、无清除单题作答、无复练前后对比。任务书第六节第4项要求全部未实现。

### A6. 交卷后状态锁定，无法复练 —— 【已确认缺陷，P1】

`quiz-template.html:294-298`：`submitted=true` 后所有选项按钮 `disabled`，`:303` 点击直接 return。唯一出路是"重做全部"（销毁历史）。

- "交卷后的状态是否允许错题复练而不影响历史成绩"——**答案：不允许**。历史成绩与当前作答共用同一份 `answers/results` 状态，无 attempts 概念。

### A7. localStorage 行为 —— 【已确认缺陷（静默失败），P1】

`quiz-template.html:167-177`：save/restore 均 try/catch **静默吞错**。

- 存储被禁用/配额满/隐私模式时：用户答题全程无提示，刷新后进度全丢。
- file:// 下 Chrome/Edge 通常允许 localStorage，但企业策略/某些浏览器配置会禁用；当前实现无探测、无提示、无导出兜底。
- 附带：STORE_KEY = `"cqb:" + QUIZ.title`——**同名不同内容的题库会串记录**（未含题数/指纹）。

### A8. 降级处理 —— 【部分实现，P2】

已实现：PDF 缺依赖提示安装命令（:110）；BadZipFile 明确报错（:65,88）；空文本提示纯图片路径（:63,129）；多文件同名图片用源文件子目录隔离（:257）。

缺失：扫描 PDF 无"文字已提取/需OCR/未能识别"**三态区分**（只有"未提取到文本"单一提示）；无文件大小/解压总量/条目数/图片数量**资源上限**（zip 炸弹无防护：zipfile 会忠实解压任意大成员）；docx 图片仅按 media 文件名序（非文档序）；pptx 幻灯片按文件名序（非 presentation.xml 演示顺序）。

### A9. 注入风险 —— 【基本防御到位，P2 收尾】

已实现：`js_safe_json` 全量 `<`→`\u003c`（quiz_toolkit.py:395）；MD `md_escape`（:330）；图片 src 白名单+`@key`（template:140）；DOM 渲染全用 textContent/createTextNode。

待补：新增证据字段（source_quote 等）渲染时同样走 textContent（设计约束）；evidence_status 徽标等 UI 元素不受数据污染（静态枚举映射）。**无高危项**。

### A10. 能力描述与实现一致性 —— 【已发现 2 处不符，P1】

1. `quiz-format.md:138`"魔数与扩展名一致" vs 实现是"魔数属于任一已知图片"（见 A2）。
2. SKILL.md 交付话术"错题回顾 → 重做错题"中"重做错题"实际是"重做全部"（销毁式，见 A5/A6）。

### 额外发现（任务书未列）

- **B1** extract_text.py 无 `source_manifest.json` / `source_id` / `segment_id` 产物（A3 根因）。
- **B2** docx 表格内容被压平进正文流，行列结构丢失（影响表格类知识点出题质量）。
- **B3** 刷题页无题目导航（上一题/下一题/题号面板）、无收藏标记、无键盘操作、无章节筛选。
- **B4** 无学习报告（考点掌握度/历次成绩/薄弱点/导出导入）。
- **B5** 题库首页缺失（打开即全部题目长列表，"开始学习的路径"= 直接滚动）。
- **B6** 无考试/复习模式区分（只有交卷后才出反馈的单一模式）。
- **B7** 简答自评与客观判分在成绩单中混合口径（"已评 x/y"仅一行文字，未分列）。
- **B8** 移动端仅有 viewport meta，无响应式断点；工具栏按钮在窄屏溢出换行混乱。
- **B9** 无生成工作流的中间产物（考点清单/覆盖计划），题量分配靠 LLM 即兴，易集中在材料前部（SKILL.md 有文字要求但无结构化约束）。
- **B10** PDF 依赖三选一探测逻辑中 PyPDF2 分支的 `extract_text` API 在老版本可能不存在（未实测，标【未验证】）。
